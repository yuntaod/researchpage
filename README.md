# yuntaodu.me

Personal research website of Yuntao Du. Jekyll site styled after
[Jon Barron's template](https://github.com/jonbarron/jonbarron.github.io),
with publications generated from BibTeX.

## Code structure

```
_layouts/barron.html          page shell (head, header, footer, news toggle)
_layouts/barron-post.html     blog post shell (+ MathJax + citation renderer)
_layouts/bib.html             how ONE publication entry renders
_includes/barron_header.html  photo, name, link row, nav (shared by all pages)
_includes/figure.html         responsive figures for blog posts
_includes/scripts/mathjax.html
assets/css/barron.css         the single stylesheet

_pages/about.md               homepage (bio, pillars, news, selected pubs, honors, service)
_pages/publications.md        /publications/ (by year, with topic filter tags)
blog/index.html               blog index
_posts/*.md                   blog posts (Markdown)
assets/bibliography/*.bib     per-post citation files
_bibliography/papers.bib      ALL publications (source of truth)
_news/*.md                    news items
_data/honors.yml              awards list
_data/services.yml            service list (abbrs = what shows on homepage)
notes/                        legacy static study notes (not linked in nav)
```

## How to update content

| Task | Edit | Notes |
|---|---|---|
| Add a paper | `_bibliography/papers.bib` | One BibTeX entry. Useful fields: `abbr` (short venue), `arxiv`, `pdf`, `code`, `slides`, `website`, `blog`, `topic` (for by-topic page), `selected = {true}` (shows on homepage), `manuscript = {true}` (Manuscripts section), `coverage = {Outlet\|url; Outlet2\|url2}` (renders "Coverage: [Outlet]") |
| Add news | new file in `_news/` | Front matter: `date` + `inline: true`; body is Markdown. Homepage shows newest 5, rest behind "Show more news" |
| Add an honor | `_data/honors.yml` | `name` (bold), `url`, `suffix`, `year`, optional `extra_links` (rendered as "Coverage: [...]") |
| Update service | `_data/services.yml` | Edit the `abbrs` line (what displays); keep `items` (full names) in sync. Order: most recent year first |
| Write a blog post | `_posts/YYYY-MM-DD-name.md` | `layout: barron-post`. Markdown + `$$math$$`. Citations: `<d-cite key="x"></d-cite>` + a same-named `.bib` in `assets/bibliography/` (set `bibliography:` in front matter). Figures: `{% include figure.html path="..." %}` followed by `<div class="caption">...</div>` |
| Edit bio / pillar cards | `_pages/about.md` | Raw HTML. ⚠️ Every `<div>` must be closed — one missing `</div>` scrambles the whole homepage (kramdown falls out of HTML mode) |
| Change the design | `assets/css/barron.css` + layouts | |

## Local development

```bash
rbenv local 3.3.0          # needs Ruby >= 3 (system Ruby 2.6 is too old)
bundle install
bundle exec jekyll serve --watch
# open http://127.0.0.1:4000  — edits rebuild automatically (~2s), then refresh browser
```

Local "ImageMagick: convert not found" errors are harmless: responsive
`.webp` images are only generated on CI (which installs ImageMagick); locally
the pages fall back to the original PNGs.

## Branches & deployment

GitHub Pages serves yuntaodu.me from **one branch at a time**, chosen in
**Settings → Pages → Source** ("Deploy from a branch"). Two independent
pipelines exist — each source branch carries its own `.github/workflows/deploy.yml`:

| Push to | CI builds and publishes to | Contains |
|---|---|---|
| `master` / `main` | `gh-pages` | old al-folio site |
| `barron-style` | `barron-pages` | new Barron-style site |

- **Switch the live site**: change the branch dropdown in Settings → Pages
  (`gh-pages` ↔ `barron-pages`). Takes ~1 minute, no rebuild, reversible.
- Every push to a source branch redeploys its output branch automatically
  (watch the *Actions* tab; a deploy takes 2–4 minutes).
- Never edit `gh-pages` / `barron-pages` by hand — they are build artifacts,
  overwritten on every deploy.
- GitHub Pages cannot serve the source branches directly: publications are
  generated by jekyll-scholar, which Pages' built-in builder does not run.
- If the new design becomes permanent: merge `barron-style` into `master`,
  change `branch: barron-pages` to `branch: gh-pages` in the merged
  `deploy.yml`, and point Pages back at `gh-pages`.
